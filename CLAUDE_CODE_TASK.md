# ТЗ: опублікувати візуалізації з топології на GitHub + GitHub Pages

## Контекст

Ця папка — готовий проєкт: статичні HTML-сторінки з інтерактивними доведеннями для курсу топології. Код сторінок уже готовий і перевірений. **Не змінюй вміст `compactness.html`, `banach.html` та `index.html`**, якщо тільки в пунктах нижче прямо не сказано інакше.

Структура:

```
index.html            головна сторінка з посиланнями
compactness.html      основна робота: повний + цілком обмежений ⇒ компактний
banach.html           додатково: теорема Банаха про нерухому точку
reports/              звіти (PDF/DOCX/MD, кладе автор перед запуском)
README.md
CLAUDE_CODE_TASK.md   цей файл
```

## Мета

Публічний репозиторій на GitHub і робоче посилання GitHub Pages, яке можна надіслати викладачу.

## Кроки

1. **Перевір середовище.**
   - `git --version` і `gh --version`. Якщо `gh` не встановлений, підкажи команду встановлення для ОС користувача і зупинись.
   - `gh auth status`. Якщо користувач не залогінений, попроси його виконати `gh auth login` (не роби цього за нього) і чекай.
   - Перевір, що в `git config user.name` і `user.email` щось задано. Якщо ні — спитай у користувача.

2. **Перевір файли.**
   - Усі три `.html` на місці й відкриваються. Можна підняти `python -m http.server` і переконатися, що сторінки віддаються зі статусом 200.
   - У `reports/` має бути хоча б один звіт. Якщо там лише `.gitkeep`, нагадай користувачу експортувати звіти з Claude у PDF і покласти їх сюди. Продовжуй тільки після його відповіді (він може сказати «без звітів»).
   - Перейменуй звіти на латиницю без пробілів, наприклад `report-compactness.pdf` і `report-banach.pdf` (кирилиця і пробіли в URL незручні).

3. **Створи `.gitignore`** з типовим сміттям: `.DS_Store`, `Thumbs.db`, `*.swp`, `.vscode/`, `.idea/`.

4. **Ініціалізуй репозиторій і зроби перший коміт.**
   - `git init -b main`, `git add .`, коміт з повідомленням `Інтерактивні візуалізації доведень з топології`.

5. **Створи репозиторій на GitHub.**
   - Назва: `topology-visualization`. Якщо така вже зайнята в акаунті, спитай у користувача іншу.
   - Публічний (інакше Pages на безкоштовному плані не працюватиме):
     `gh repo create topology-visualization --public --source=. --remote=origin --push --description "Інтерактивні візуалізації доведень з топології"`

6. **Увімкни GitHub Pages з гілки `main`, папки `/`.**
   - `gh api -X POST repos/{owner}/topology-visualization/pages -f "source[branch]=main" -f "source[path]=/"`
   - Якщо відповідь 409 (Pages уже ввімкнено), це нормально.
   - Дочекайся збірки: опитуй `gh api repos/{owner}/topology-visualization/pages/builds/latest`, поки `status` не стане `built` (зазвичай 1–2 хвилини). Якщо `errored`, покажи помилку.

7. **Перевір, що сайт живий.**
   - Отримай `html_url` з `gh api repos/{owner}/topology-visualization/pages`.
   - Перевір `curl -sI` для `index.html`, `compactness.html`, `banach.html` і кожного файлу з `reports/` — усі мають повертати 200.

8. **Онови посилання.**
   - У `README.md` заміни рядок `_посилання додасться після публікації_` на справжні посилання: головна, обидві сторінки, кожен звіт.
   - В `index.html` додай під двома картками посилання на звіти з `reports/` (простий список, без зміни стилю сторінки). Якщо звітів немає, нічого не додавай.
   - Закоміть (`Додано посилання на GitHub Pages і звіти`), запуш і дочекайся нової збірки Pages.

9. **Фінальний звіт користувачу** (коротко):
   - посилання на репозиторій;
   - посилання на GitHub Pages: головна, `compactness.html`, `banach.html`, звіти;
   - готовий текст листа викладачу на 3–4 речення українською з цими посиланнями.

## Обмеження

- Не видаляй і не переписуй HTML-сторінки, не додавай фреймворків, збирачів чи залежностей.
- Не роби force-push і не змінюй інші репозиторії користувача.
- Не зберігай токени та паролі у файлах.
- Якщо щось незрозуміло або крок падає двічі поспіль, зупинись і спитай користувача.
